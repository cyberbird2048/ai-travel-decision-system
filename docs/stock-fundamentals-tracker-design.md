# 长期股票基本面追踪系统 — 设计构思

> 目标：像巴菲特一样"拥有公司"式地追踪股票——不做短线信号，只回答一个问题：
> **"这家公司还是不是我当初买入（或想买入）时的那家公司？"**

---

## 一、核心理念

1. **档案驱动，不是行情驱动。** 每只股票是一份"公司档案"（dossier），价格只是档案里最不重要的一栏。
2. **论点先行（Thesis-first）。** 每只股票必须先写下投资论点和 **Kill Criteria（什么情况下我会承认看错）**，之后所有追踪都是在验证或证伪这份论点。
3. **变化才值得报告。** 系统的默认输出是"无重大变化"——这本身就是巴菲特式的价值信息，避免为了输出而制造噪音。
4. **每个结论都要有出处。** LLM 生成的所有数字和事实必须附带来源（财报页码 / 新闻链接 / 13F 文件），防幻觉。

## 二、每只股票追踪的八个维度

### 1. 基本面（Fundamentals）
- 十年期关键指标：营收、毛利率、营业利润率、ROIC、ROE、FCF、Owner Earnings（巴菲特口径）、资产负债率、股份数变化（回购/稀释）
- 每季财报后刷新，重点不是数字本身，而是 **趋势和拐点**：连续 N 季恶化自动升级为黄灯

### 2. 护城河（Moat）
- 类型标签：网络效应 / 转换成本 / 无形资产（品牌、专利、牌照）/ 成本优势 / 有效规模
- 每个护城河记录：**宽度（宽/窄）+ 趋势（加深/稳定/侵蚀）+ 证据**
- 量化佐证：定价权（毛利率 vs 同行）、客户留存、市场份额变化
- 设立 **对照组**：每只股票绑定 2-3 个竞争对手，护城河判断必须相对于对手做

### 3. 商业模式（Business Model）
- 一页纸描述：怎么赚钱、客户是谁、收入结构、资本密集度、周期性
- 单位经济（unit economics）变化追踪
- 变化频率低，仅在年报 / 重大战略转向时刷新

### 4. 关键决策（Key Decisions）
- 时间线形式追踪：并购、分拆、大额资本开支、管理层更替、回购/分红政策变化、战略转向
- 每条决策记录当时的判断（好/坏/存疑 + 理由），**一年后回看复盘**——这是检验管理层资本配置能力的核心方法
- 附带：内部人买卖（insider trading）追踪

### 5. 机构观点（Institutional Views）
- 13F 季度扫描：知名长期投资者（Berkshire、Himalaya、Baillie Gifford 等自定义名单）的增减仓
- 明星基金经理的股东信、访谈中提及该公司的观点摘录
- 卖方评级只记录极端分歧（一致看多突然出现看空），不追日常调价

### 6. 关键节点兑现（Milestones / Watch Items）
追踪"论点里押注了、但还没兑现"的前瞻性事项，例如：苹果的 AI 进度（Apple Intelligence 落地、Siri 重构）、折叠屏进度、新药三期数据、产能爬坡等。

每个节点是一条结构化记录：

```yaml
- item: Apple Intelligence / 新 Siri 落地
  来源: 管理层承诺 | 行业预期 | 我的论点假设   # 三种来源要区分，问责对象不同
  首次提出: 2024-06 WWDC
  预期时间: 2026 春
  当前状态: 延期 | 按计划 | 提前 | 已兑现 | 已放弃
  最新证据: [链接] 一句话
  对论点的影响: 该节点是论点支柱之一 / 加分项 / 无关紧要
  跳票次数: 2        # 连续跳票自动升级为管理层黄灯信号
```

要点：
- **每季财报 / 重大发布会后由 Sonnet 逐条核对状态**，日常新闻扫描时 Haiku 顺带标记"该新闻涉及哪个 watch item"
- **跳票是强信号**：同一节点跳票 ≥2 次，自动在方向灯"管理层"和"论点"两栏打黄灯——执行力恶化往往先于财务数字恶化
- **区分"承诺"和"市场想象"**：管理层从没承诺过的事（如苹果折叠屏在正式官宣前）跳票不能怪管理层，但要记为"论点假设未验证"
- 节点兑现/放弃后不删除，移入历史区——积累下来就是这家公司**执行力的量化记录**

### 7. 关键上下游（Value Chain）
公司不是孤立的，上下游往往是基本面的**领先指标**：供应商砍单、下游客户资本开支收缩，通常比公司自己承认需求疲软早一到两个季度。

每只股票维护一张价值链地图：

```yaml
上游（供应商/依赖）:
  - 名称: 台积电
    依赖度: 关键（不可替代）| 重要 | 可替代
    风险: 单一供应 / 地缘 / 产能
    监控信号: 其财报中相关产线产能利用率、涨价动作
下游（客户/渠道）:
  - 名称: 前五大客户占营收 X%（来自年报客户集中度披露）
    监控信号: 客户自身财报、资本开支指引、砍单传闻
互补生态: 开发者、内容方、配件厂等（平台型公司尤其重要）
```

要点：
- **议价能力双向标注**：对上游能否压价、对下游能否提价——这直接是护城河（成本优势/定价权）的证据，两个维度互相引用
- **领先指标清单**：为每只股票挑 3-5 个上下游公司的财报/月度数据作为前瞻信号（如苹果 → 台积电月度营收、立讯/鸿海指引；英伟达 → CoWoS 产能、云厂商 capex），财报季顺带用 Haiku 扫一遍
- **集中度红线**：客户/供应商集中度超过阈值（如单一客户 >20% 营收）记入风险清单，恶化时触发黄灯
- **传导分析**：重大行业事件（涨价、断供、技术替代）发生时，Sonnet 沿价值链地图推演对本公司的传导路径，而不是就事论事
- 上下游公司若本身也在观察池中，档案互相链接，一次数据采集多处复用

### 8. 方向灯（Signal Dashboard）
每只股票一行五盏灯，每盏 🟢🟡🔴 + 一句话理由：

| 灯 | 判断依据 |
|---|---|
| 基本面 | 趋势指标是否恶化 |
| 护城河 | 侵蚀证据是否出现 |
| 管理层 | 资本配置记录 + 诚信事件 |
| 估值 | 当前价格 vs 估值锚区间（见下） |
| 论点 | Kill Criteria 触发了几条 + 关键节点跳票情况 |

**估值锚**：不做精确 DCF，只维护一个"合理价值区间"（悲观/基准/乐观三档），每次年度复盘更新一次。方向灯只回答"贵/合理/便宜"。

## 三、你可能没想到的补充（建议加上）

1. **Kill Criteria / 反面论点**：每只股票强制维护一份"空头会怎么说"（devil's advocate），每次刷新时由 LLM 扮演空头攻击当前论点。多数人只追多头证据，确认偏误是这类系统最大的敌人。
2. **判断的版本历史**：档案放在 git 里，每次刷新是一次 commit。一年后可以 diff 出"我的判断是怎么演变的"，避免后视镜偏差，这是复盘能力的基础。
3. **事件驱动 + 定期刷新双轨**：不只定期跑，重大事件（财报发布、8-K、管理层变动、股价单日 ±10%）触发即时深度分析。
4. **能力圈标签**：每只股票标注"理解深度"（深/中/浅），浅的股票方向灯自动降权提示。
5. **"无变化"也是输出**：周报里明确写"本周 X 只股票无重大变化"，训练自己忍住不动。
6. **观察池分层**：持仓 / 高关注（等价格）/ 观察（等验证）三层，刷新深度和频率不同，省 token。
7. **财报电话会追踪管理层言行一致性**：把管理层历年的承诺提取成清单，下次财报核对兑现情况。

## 四、系统架构

```
┌─ 数据采集层（免费为主）──────────────────────────┐
│ SEC EDGAR (10-K/10-Q/8-K/13F/Form4)              │
│ yfinance / FMP 免费档（价格、基础财务）           │
│ 财报电话会 transcript、公司 IR 页、新闻 RSS       │
└──────────────┬───────────────────────────────────┘
               ▼
┌─ 存储层 ─────────────────────────────────────────┐
│ stocks/<ticker>/                                  │
│   thesis.md        投资论点 + Kill Criteria       │
│   moat.md          护城河评估                     │
│   business.md      商业模式                       │
│   decisions.md     关键决策时间线                 │
│   institutions.md  机构观点                       │
│   milestones.yaml  关键节点兑现追踪               │
│   valuechain.yaml  上下游价值链地图               │
│   dashboard.json   方向灯状态                     │
│   fundamentals.json 十年指标（结构化）            │
│ 全部 markdown/json 存 git —— 人可读、可 diff      │
└──────────────┬───────────────────────────────────┘
               ▼
┌─ LLM 分析层（分级用模型，见下）───────────────────┐
│ 过滤/摘要 → 深度分析 → 空头攻击 → 更新档案+方向灯 │
└──────────────┬───────────────────────────────────┘
               ▼
┌─ 呈现层 ─────────────────────────────────────────┐
│ 静态 HTML 仪表盘（方向灯总览 + 档案页）           │
│ 周报/季报 markdown + 推送（邮件/Telegram）        │
└───────────────────────────────────────────────────┘
```

技术选型建议：Python 脚本 + GitHub Actions 定时任务（免服务器）+ 静态站（GitHub Pages），数据用 JSON/markdown 而非数据库，规模 ≤ 50 只股票完全够用。

## 五、刷新节奏与模型分工（token 成本控制）

| 任务 | 频率 | 模型 | 说明 |
|---|---|---|---|
| 新闻/公告扫描过滤 | 每日 | **Haiku** | 只做"是否值得关注"二分类 + 一句话摘要，99% 被丢弃 |
| 重要事件初步分析 | 事件触发 | **Sonnet** | 判断是否影响论点/方向灯 |
| 财报深度分析 | 每季 | **Sonnet** | 更新 fundamentals + 各维度档案 + 管理层承诺核对 |
| 13F / 机构观点 | 每季 | **Haiku** 提取 + **Sonnet** 汇总 | |
| 空头攻击 + 年度复盘 | 每年/重大变化 | **Sonnet**（或手动升级 Opus） | 全档案重审 + 估值锚更新 |
| 周报生成 | 每周 | **Haiku** | 只汇总已有结论，不做新分析 |

省 token 关键技巧：
- **漏斗结构**：Haiku 过滤 → 只有通过的才进 Sonnet，日常 90%+ 调用是 Haiku
- **Prompt caching**：公司档案作为长 system prompt 缓存，批量处理同一公司的多条新闻
- **Batch API**：定时任务全部走 batch（半价），实时性不重要
- **增量分析**：每次只把"新数据 + 档案摘要"喂给模型，不重复分析历史

## 六、落地路线图

1. **MVP（第 1 周）**：手动建 3 只股票档案（thesis/moat/dashboard），跑通"季报 → Sonnet 分析 → 更新档案 + 方向灯"单条链路
2. **自动化（第 2-3 周）**：EDGAR + 新闻采集，Haiku 每日过滤，GitHub Actions 定时
3. **完善（第 4 周+）**：13F 追踪、空头攻击、静态仪表盘、推送
4. **长期**：年度复盘流程、判断 diff 复盘工具、观察池分层
