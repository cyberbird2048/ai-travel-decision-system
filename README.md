# 旅行规划师 / AI Travel Planner

一个按需接入各类接口的旅行规划系统，从原来的"出行天气适配度"工具演化而来。

输入出发地、目的地、日期和想做的事，它会：

1. **设计线路**：结合目的地素材库与逐日天气，生成逐日行程（雨天自动切换室内优先）。
2. **匹配航班**：内置航线示例库兜底，可选接入实时航班接口（AviationStack）。
3. **确认落地交通**：每个目的地的机场进城方案（时长/价格/适用场景）。
4. **评估出行适配度**：沿用原系统的"活动暴露度 × 天气风险"模型，官方警告与硬红线优先。
5. **生成携带物品清单**：按天气区间与活动类型自动生成，H5 上可勾选打包进度。
6. **推荐美食与娱乐**：目的地知识库中的餐厅、市场、观景、夜生活等。
7. **形成动态出行 H5**：手机友好的行程页，打开时自动刷新天气并重算适配度与清单，带出发倒计时、"今天"高亮，可通过链接分享（计划编码在 URL 中，无需服务端）。

## 架构

```text
index.html / app.js        规划师主界面（需求输入 → 完整计划）
h5.html / h5.js / h5.css   动态出行 H5（分享页，打开即刷新）
engine/planner.js          规划引擎：适配度、行李清单、逐日线路
adapters/registry.js       接口注册中心：按需接入，Key 存浏览器本地
adapters/weather.js        天气：Open-Meteo（全球免 Key，16 天预报）
adapters/flights.js        航班：示例库兜底 + 可选 AviationStack 实时接口
adapters/destinations.js   目的地知识库：机场、落地交通、美食、娱乐
adapters/hko-weather.js    保留的 HKO 适配器（香港官方警告）
docs/planner-design.md     规划层设计蓝图（交互、接口选型、偏好学习、路线图）
docs/codex-handoff.md      执行交接单（M1 任务拆解、接口契约、验收清单）
```

> **接手开发前先读 `docs/codex-handoff.md`**：当前代码是 M0 骨架，M1 的技术栈约束、文件结构、接口签名与 Definition of Done 全在交接单里；设计意图与取舍理由见 `docs/planner-design.md`。两份文档冲突时以交接单为准。

**按需接入接口**：点击右上角"接口设置"，粘贴对应服务的 API Key 即从示例模式切换到实时模式；不配置也能完整跑通规划流程，但示例数据会明确标注"仅为量级参考"。

## 当前支持

- 出发地：深圳、广州、上海、北京、杭州、成都、香港、新加坡。
- 目的地：香港、东京、大阪、曼谷、新加坡、首尔、台北（`adapters/destinations.js` 中可扩展）。
- 活动：山径徒步、露营过夜、城市漫游、美食探店、海滩活动（可多选）。
- 运行方式：纯静态 HTML/CSS/JS，无构建依赖。

## 运行

```bash
python3 -m http.server 8080
```

访问 `http://localhost:8080/` 生成计划，点击"打开出行 H5"查看分享页。

## 判断边界

- 官方警告和硬性安全阈值优先于行程沉没成本。
- 日期超出 16 天预报窗口时不生成适配度分数，只给出复查时点。
- 示例航班/价格明确标注，不可用于购票决策；接入实时接口后自动切换。
- 目的地知识库为公开常识性信息，价格为量级参考，出行前以官方为准。

## 隐私与安全

- 计划与 API Key 只保存在浏览器本地（localStorage），仓库和服务器不存任何个人数据。
- 免 Key 接口仅调用 Open-Meteo 与香港天文台公开数据。
- 分享链接中的计划为你主动生成的行程内容，请自行判断分享范围。
